## 1. Design intent in one paragraph

Vantage looks like an **observatory**: a dark, quiet instrument where the data surfaces are
opaque and precise and the controls float above them in thin glass. The hero object is not a
chart — it is the **query card**: the plain-English question, the spec the model produced, and the
SQL that actually ran, stacked so the eye reads *question → structure → proof* before it reaches a
number. Every number carries its status (complete, in progress, empty, stopped) in the same
typographic voice, because in analytics a silent partial is worse than a loud refusal.

## 2. Design language: "Observatory glass"

Distinct from Weft on purpose — a different product should not share a palette — but the same
discipline: glass on the navigation layer only, data on opaque surfaces, one accent, OKLCH tokens.

### 2.1 Layering

| Layer | Material | Examples | Never |
|-------|----------|----------|-------|
| L0 Ground | deep indigo-black with two slow radial glows (accent + violet) | body | — |
| L1 Content | **opaque** slate surfaces | query card, result panels, tables, SQL panel, heatmap | blur, transparency behind data |
| L2 Navigation | **glass** | left rail, top command bar, filter chips row, status toasts-that-are-not-toasts (inline), the Ask input's floating container | glass in glass; charts behind glass; text on raw glass |

Glass regions on screen at once: ≤ 3 (rail, command bar, one transient).

### 2.3 Status vocabulary (one component, used everywhere a number appears)

| Status | Chip | Colour | Copy |
|--------|------|--------|------|
| `complete` | `● Complete · 0.41 s` | ok | footer: `data until 09:12 · tz Asia/Kolkata` |
| `in_progress` (some buckets) | `◐ Partly in progress` | warn | hatched cells/bars + tooltip *"This period isn't over yet; the number will change."* |
| `empty` | `○ No events matched` | ink-2 | *"No events matched these steps in this range."* — never the same rendering as an error |
| `timed_out` | `■ Stopped after 5 s` | bad | *"Showing nothing rather than a partial answer. Narrow the date range or add a filter."* |
| `truncated` | `▤ Showing top 50 of 1 284` | warn | always the real N |
| `refused` | `⊘ Refused` | bad | *"The model's output is not a query the grammar can express."* + raw output |
| `refused_by_database` | `⊘ Refused by the database` | bad | *"This should be impossible; it has been logged as a bug."* |
| `ts_adjusted` (secondary) | `↺ 3 % of events on adjusted clocks` | ink-3 | tooltip explains the 60 s rule |

### 3.2 Flows (each is a numbered stepper in the prototype, with a "Next" control)

| # | Flow | Steps |
|---|------|-------|
| F1 | **Ask → see the SQL** | type question → spec card appears (violet) → SQL slides in (amber) → result renders → footer status |
| F2 | **Hostile ask refused** | type "drop the events table" → `⊘ Refused` card with raw model output → nothing ran → audit row appears |
| F3 | **Edit spec, re-run** | *Edit spec* → change window → SQL diff highlighted → new numbers |
| F4 | **Timeout** | wide range → `■ Stopped after 5 s` → suggestion chips (*Narrow to 30 days*, *Add filter*) |
| F5 | **Empty ≠ error** | unknown event name → `○ No events matched` (calm) vs DB down → error card (red) side by side |
| F6 | **Retention in progress** | hover last column → hatched tooltip; toggle curve |
| F7 | **Ingest with duplicates** | paste batch → response `accepted 498 · duplicates 2` → Events count updates |
| F8 | **Identify / merge** | anonymous → user_id → person merge notice → funnel footer `persons merged since: 1` |
| F9 | **MCP install → tool call** | copy config → restart → Claude transcript with `run_funnel` args and the tool result's `sql` |
| F10 | **Light theme / reduced transparency** | toggles; every screen remains legible |

## 4. Components

- **Left rail (glass, 64 px collapsed / 220 px expanded):** Ask, Funnel, Retention, Paths, Events, History, Projects, MCP, Health. Keyboard 1–9.
- **Command bar (glass):** project switcher, date range, timezone label (always visible: `Asia/Kolkata`), theme, ⌘K.
- **Query card (opaque):** three stacked blocks with left borders in violet (spec) and amber (SQL); collapsible; the SQL block has *Copy*, *Explain plan* (opens `EXPLAIN` text), and a diff view when re-run.
- **Funnel bars:** horizontal, one per step, height 44 px, label left, count + `% prev` + `% start` right in tabular mono; step colour `--c1..`; drop-off shown as a dimmer segment.
- **Retention heatmap:** `<table>`, cells 44 × 32, colour from `--s0..--s5` on a global 0–100 % scale, hatched (diagonal 45° repeating-linear-gradient) when `in_progress`; row header = cohort bucket + size; hover tooltip.
- **Transitions table:** rank, from → to, persons, % of start, median gap; flow columns as 5 narrow stacked bars.
- **Status chip:** §2.3, `role="status"`; `refused*` and `timed_out` use `role="alert"`.
- **Inline notice strip** (opaque) above results for merges, adjusted clocks, truncation. No auto-dismiss toasts anywhere.

## 5. Motion and accessibility

Same tokens as Weft's discipline: 120/220/400 ms, `--ease`, disabled under reduced motion. Focus
ring 2 px accent; rail and bar never obscure focus. Every status = word + icon + colour. Heatmap
cells carry `aria-label="Aug 12 cohort, day 3: 41 % (in progress)"`.

## 6. What the prototype must contain (for the build to port)

Static HTML + CSS + vanilla JS, no framework. S0–S9 as switchable screens; F1–F10 as steppers
with realistic data from the demo dataset (`signup → create_project → invite_teammate`, August,
`Asia/Kolkata`). Real copy from §2.3. Dark and light. Tokens verbatim from §2.2.
